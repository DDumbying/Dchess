# Game Replay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Step through saved or any PGN games, and play on from any position.

**Architecture:**
- The core `game/replay.c` lists a PGN file's games and reads one game's moves; it has unit tests.
- The TUI adds a replay mode to the existing game screen.
- A replay can be opened from the stats page, the launcher card, or a `--replay` picker.

**Tech Stack:** C, ncursesw, `make test`, tmux.

**Spec:** `docs/superpowers/specs/2026-09-27-replay-design.md`

> Terse by request. The spec holds the API, keys and limits.

## Global Constraints

- Zero warnings under `-O2 -Wall`; use `make -B` after a header change.
- Core never includes ncurses. Sparse comments. No attribution trailers.
- Clip every name with `mvw_fit`/`mvw_clip`.
- tmux: session `dchess-t` with exact targets `'=dchess-t:'`, and a scratch HOME/XDG. Typed game commands need `i` first.

## Review Focus

1. **Movetext written by other programs:**
   - a token split across lines;
   - `1.e4` with no space;
   - `e8=Q+`, `exd6 e.p.`, `O-O+`, `Nbd7` / `N1f3`;
   - lowercase `o-o`.

   It must play correctly or stop with a clear `err`. Test in Task 1.
2. **A file with junk:** stray text between games, a game with tags but no moves, a missing final newline, a UTF-8 BOM. The listing must stay correct. Test in Task 1.
3. **A game of 1,024+ plies:** the reading stops at the limit without overflowing. Test in Task 1.
4. **Stepping at the edges:** ← at ply 0 and → at the end do nothing; auto-play stops at the end; resizing during a replay. tmux check in Task 3.
5. **Play from here at ply 0 or at a finished position** (mate/stalemate): the new game starts, or the finished state shows, with no engine hang. tmux check in Task 3.

### Task 1: `replay.c` core

**Files:** Create `headers/game/replay.h`, `src/game/replay.c`, `tests/test_replay.c`. Modify `headers/game/records.h` and `src/game/records.c` (`offset`), and `tests/test_records.c`.

- [ ] **Step 1: Tests.** In `test_replay.c`, write fixture PGN text to temporary files. Cover:
  - **round trip:** play `e4 e5 Nf3 Nc6 Bb5 a6 O-O` in a `GameState`, `pgn_write` it, then `replay_read` gives the same `Move`s;
  - **skipping:** `{c}`, `(1... d5 (1... c5))`, `; x`, `$1`, `12...`;
  - **move forms:** `0-0` = `O-O` and lowercase `o-o`; a promotion `e8=Q+` from `4k3/P7/8/8/8/8/8/4K3 w - - 0 1` (`a8=Q+`); `1.e4` with no space; `Nbd7`-style disambiguation;
  - **errors:** an illegal token gives the moves before it and an `err` containing `stopped at move`;
  - **FEN:** a `[FEN "..."]` game uses its start position;
  - **listing:** a three-game file, with junk between games, a game with no moves, and no final newline, gives count 3 with correct white, black and result, and each offset opens with `replay_read`;
  - **format quirks:** CRLF and a UTF-8 BOM;
  - **limits:** a 65 MiB sparse file is refused; a generated 1,100-ply shuffle (`Nf3 Nf6 Ng1 Ng8` repeated) stops at `MAX_MOVE_HISTORY`;
  - **names:** `[White "Big \"Al\""]` lists as `Big "Al"`.

  In `test_records.c`: `r[i].offset` is the position of each `[Event` line.
- [ ] **Step 2:** `make build/test_replay` → undefined `replay_*`. `test_records` → no member `offset`.
- [ ] **Step 3: Implement.**
  - The tag parser is copied from `records.c` (made public as `records_parse_tag` in `records.h`, rather than duplicated).
  - Tokenizer:
    - read the movetext after the tags up to the next `[` line at depth 0;
    - skip `{…}`, nested `(…)`, `;`-to-end-of-line and `$\d+`;
    - split on whitespace and after `N.`/`N...`;
    - drop result tokens and `e.p.`.
  - Matching:
    - normalise both sides: strip trailing `+#!?`, map `0`→`O`, and uppercase a leading `o`;
    - `generate_moves`, then for each move that is legal after `make_move`, compare `san_write` normalised;
    - require exactly one match, then play it on a local `Position` (use `game_play` on a scratch `GameState` for correctness).
  - `records_load` sets `r->offset` to the `ftell` before the game's first tag.
- [ ] **Step 4:** Run `make -B test` → all pass, 0 warnings. Commit `feat(replay): read games from PGN files`.

### Task 2: `--replay` flag and the picker

**Files:** `headers/utils/cli.h`, `src/utils/cli.c`, `tests/test_cli.c`, `src/main.c`. Create `headers/tui/replay_tui.h` and `src/tui/replay_tui.c`.

- [ ] **Step 1: Test.** `--replay /x.pgn` → `args.replay == "/x.pgn"` and it counts as a gameplay flag, so the launcher is skipped. `--replay` with no value is an error.
- [ ] **Step 2:** Watch it fail. Implement the flag (a `char replay[512]`) and the help line.
- [ ] **Step 3: main.c.** When `args.replay[0]`:
  - `replay_list` on the file; on failure, print the error and exit 1 before curses starts;
  - otherwise run `tui_init` and then `replay_browse(&state, &list, path)`.
- [ ] **Step 4: `replay_tui.c`.**
  - `int replay_browse(TUIState*, ReplayList*, const char *path)`:
    - with one entry, open it directly;
    - with more, show the picker: rows `%4d  White – Black  result  date  event` through `mvw_fit`; ↑↓, PgUp/PgDn, ⏎ opens, esc returns 0;
    - after a replay, come back to the picker.
  - `int replay_open(TUIState*, const char *path, long offset, int from)` does `replay_read` into a heap `ReplayGame`, then runs the replay loop (Task 3). It returns 1 when the user chose play-from-here (the caller then runs the normal game), and 0 on esc.
- [ ] **Step 5:** Run `make -B test`. Commit `feat(replay): --replay flag and game picker` (the loop body lands in Task 3; until then, `replay_open` shows the first position and waits for esc).

### Task 3: Replay mode on the game screen

**Files:** `headers/tui/tui.h`, `src/tui/tui.c`, `src/tui/replay_tui.c`, `src/tui/panels.c`, `src/tui/render.c` (only if the moves highlight needs it).

- [ ] **Step 1: State.** `TUIState` gains `ReplayGame *replay; int replay_ply, replay_auto;`.
- [ ] **Step 2: Loop in `replay_open`.**
  - Create the screen windows as `tui_run` does (factor its window setup into a `screen_create`/`screen_paint` reuse; both already exist and are static in `tui.c`, so expose them as `tui_screen_open/paint/close` in `tui.h`).
  - `goto_ply(k)`: `game_load_fen(start or standard)`, then `game_play` for the first k moves, then `game_update_status`.
  - Keys as in the spec. Auto-play uses `timeout(1000)`, and `ERR` steps. `KEY_RESIZE` recreates the windows.
- [ ] **Step 3: Panels.** When `state->replay`:
  - the command bar shows the spec's `REPLAY · k/n · …` line;
  - the engine panel shows `replay`;
  - the clocks show `—`;
  - the moves panel marks ply k (reverse video on that SAN).
- [ ] **Step 4: Play from here.**
  - Take the FEN of the current position (`position_to_fen`) and fill a `CliArgs`: `fen`, and the active profile's players, book and theme (the `word_player` logic: use `launcher` helpers if they are public, otherwise the same `profile_player_args` mapping in `tui.c`).
  - Free the replay, call `tui_init(state, &args)`, and return 1. The caller then runs `tui_run` with `show_onboarding = 0`.
- [ ] **Step 5:** Run `make -B dchess && make -B test` → 0 warnings, all pass.
- [ ] **Step 6: tmux (100×30):**
  - `--replay` with the three-game fixture: the picker, open game 2, → ×5, Home, End, space (it steps each second and stops at the end), esc returns to the picker, esc quits.
  - Review Focus 4 and 5:
    - ← at the start does nothing;
    - resizing keeps the replay;
    - p at ply 0 starts a game, and the engine replies;
    - p on a mated position shows it as finished.
  - A fixture with a bad move shows `stopped at move`.
- [ ] **Step 7:** Commit `feat(replay): step through games on the game screen`.

### Task 4: Opening from the stats page and the launcher

**Files:** `src/tui/stats_tui.c`, `src/tui/launcher.c`, `README.md`

- [ ] **Step 1: Stats page.**
  - The recent list gets `sel` (↑↓ when no other panel uses them; otherwise add `FOCUS_RECENT` with Tab).
  - ⏎ calls `replay_open(state, games_path, r->offset, FROM_STATS)`. A legacy record shows `no moves saved`.
  - esc from the replay redraws the stats page.
  - Play from here closes the stats page and returns into the game. The standalone `--stats` exits the stats page and starts the game.
- [ ] **Step 2: Launcher.**

  - In the card, ↑↓ move a cursor over the recent rows, and ⏎ opens the replay.
  - esc returns to the launcher. Play from here returns 1 from `tui_launcher`, with the state set up by Task 3.
  - The card title shows the focus accent.
- [ ] **Step 3:** Add a short README section: `Replay`, the keys, and `--replay`.
- [ ] **Step 4:** Run `make -B dchess && make -B test`.
- [ ] **Step 5: tmux:**

  - from the stats page, open and step through it, and esc returns to stats;

- [ ] **Step 6:** Commit `feat(replay): open games from the stats page and launcher`.
