# Evaluation Tuning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Texel-tune the added evaluation terms on Stockfish self-play positions, then keep the terms that measure as gains.

**Architecture:**
- The weights live in `EvalParams` (defaults are today's literals).
- `tools/genfens.c` generates the labelled positions.
- `tools/tune.c` fits K, then runs the ±1 local search with a held-out validation set.
- The output is `tuned_params.h`.

**Tech Stack:** C, pthreads, Stockfish 18, `make test`/`match`/`genfens`/`tune`.

**Spec:** `docs/superpowers/specs/2026-09-28-tuning-design.md`

> Terse by request.

## Global Constraints

- Zero warnings. The engine stays free of ncurses. No attribution trailers.
- Until tuned values are written, evaluation with the default parameters is unchanged.
- Keeping a term follows the same match rule as before; every result is ledgered.

## Review Focus

1. **Label leakage and bias:** positions from the same game are correlated, so the validation split must be by game, not by line. Task 3.
2. **Tuned weights that break symmetry or overflow** (for example large mobility times count). Symmetry test and bounds in Task 3.
3. **genfens games that end abnormally** (engine error, the 300-ply cap): no crash, and they are counted. Task 2.
4. **The tuner reading every term while the defaults keep some off:** it must evaluate with every term on, and it does not change `eval_default_options`. Task 3.
5. **A generated or included `tuned_params.h` out of sync with the `EvalParams` layout:** a compile-time size check. Task 3.

### Task 3: The tuner

- [ ] `tests/test_tune.c`, per the spec; the tuner's core (loading, σ, error, K fit, one pass) lives in `tools/tune_core.c` so the test can link it.
- [ ] `tools/tune.c`:
  - a validation split by game (genfens writes a game id);

  - writes `src/engine/tuned_params.h` with a `_Static_assert` on the parameter count.
- [ ] Run the tuning → ledger K, the errors before and after, and the passes.
- [ ] Commit `feat(tools): Texel tuner, and tuned evaluation weights`.

### Task 4: Measuring and the docs

- [ ] Matches per the spec (each term alone with the tuned weights, then the combination; then Stockfish @2300/@2600).
- [ ] Set `eval_default_options` from the results.
- [ ] Symmetry test with the tuned parameters; `make -B test`.
- [ ] Journal round 11, the README rating line, the guide (`make genfens`/`make tune`) → commit.
